# CLAUDE.md — правила работы агента в этом репозитории

Telegram-ассистент, который отвечает клиентам только по базе знаний, а остальное передаёт оператору.
Что и зачем — `README.md`; как показать за три минуты — `docs/walkthrough.md`.

## Границы

- Модель видит только найденные выдержки; системный промпт в `support_bot/llm.py` запрещает добавлять факты.
  Любая правка промпта — вместе с тестом на эскалацию (`tests/test_assistant.py`).
- Решение «ответить или передать» принимается по полю `covered` структурированного ответа, не по тексту.
  Разбор текста модели регулярками не вводить.
- Секреты только из `.env` или окружения. В логи, тесты и README значения токенов и ключей не попадают.
- Данные в `knowledge/` вымышленные (автосервис «Вектор»). Реальные цены, адреса и телефоны сюда не вносить.

## Как проверять

- `pytest` — без сети и без ключей, провайдер `fake`. Зелёный до коммита.
- Правка `knowledge/*.md` → `python n8n/build_workflow.py`; тест `test_n8n_workflow` следит, что workflow
  синхронен с базой.
- Живая проверка: `python -m support_bot --ask "вопрос" --provider anthropic` (ключ в окружении), затем
  Telegram: вопрос вне базы → карточка оператору → reply → ответ пришёл клиенту.

## Структура и расширение

- `assistant.py` — единственное место с логикой «ответить или передать». `search.py` — BM25 и стеммер.
  `llm.py` — провайдеры. `storage.py` — журнал SQLite. `bot/` — aiogram. `metrics.py` — FastAPI.
- Новый провайдер или новый поиск (например, эмбеддинги) — новый класс с тем же интерфейсом
  (`LLMProvider`, `KnowledgeSearch`), без правок `assistant.py`.
- Docker-образ собирается и проверяется в CI; `Dockerfile` и `requirements.txt` менять синхронно.
